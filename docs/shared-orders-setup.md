# 공유 수주대장 연결

공유 대상은 수주대장입니다. 다른 메뉴의 지출·작업일보·거래처·납품실적은 기존처럼 브라우저에 저장됩니다.

## 연결 준비

1. Vercel의 `cjeng` 프로젝트에 Neon Postgres를 연결합니다. 기존 DB가 있다면 전용 테이블을 사용합니다. 실제 연결 문자열은 Vercel의 서버 환경변수 `DATABASE_URL`에만 저장합니다.
2. Google Cloud Console에서 웹 애플리케이션 OAuth 클라이언트를 만들고 승인된 JavaScript 원본에 `https://cjeng.vercel.app`을 등록합니다. Sign in with Google 버튼의 ID 토큰 검증 방식을 사용하므로 client secret과 redirect URI는 사용하지 않습니다. 동의 화면과 앱 게시 상태를 실제 직원 계정으로 확인합니다.
3. Vercel Production 환경변수를 설정합니다.
   - `GOOGLE_CLIENT_ID`: 웹 OAuth 클라이언트 ID
   - `WORKSPACE_ORIGIN`: `https://cjeng.vercel.app`
   - `WORKSPACE_ALLOWED_EMAILS`: 접근을 허용한 직원 Google 이메일을 쉼표로 구분
   - `WORKSPACE_SESSION_SECRET`: 암호학적으로 생성한 32자 이상의 임의 비밀값
   - `DATABASE_URL`: Neon 연결 문자열
4. 안전하게 주입된 `DATABASE_URL` 환경에서 `npm run db:init`를 한 번 실행합니다. 이 명령은 빈 테이블을 준비하며 기존 행을 덮어쓰지 않습니다.
5. `VITE_SHARED_ORDERS=true`로 빌드한 스테이징 환경에서 직원 Google 로그인, 비허용 계정 차단, 두 세션의 동시 수정 충돌, 저장 후 다른 세션의 10초 이내 갱신을 검증합니다. 스테이징의 접속 주소는 별도 OAuth 원본과 `WORKSPACE_ORIGIN`으로 설정합니다.
6. 실제 사용 검증을 마친 커밋을 Production에 배포합니다.

## 기존 자료 이관

실제 최신 수주대장 119건이 저장된 브라우저에서 직원 계정으로 로그인합니다. 빈 공용 수주대장의 **이 브라우저의 수주 119건 가져오기** 버튼을 사용하면 기존 ID를 보존해 같은 브라우저의 지출·작업일보 연결을 유지합니다. 건수가 119건인지 확인하고 진행합니다. 기본 예제 10건인 브라우저에서는 이관하지 않습니다.

로컬 자료를 사용할 수 없을 때는 2023~2026년 CSV 4개를 가져올 수 있습니다. 다만 CSV에는 내부 ID가 없어 기존 지출·작업일보의 연결을 자동으로 복구하지 못합니다. 빈 수주일자는 빈 값으로 보존합니다. 원본 파일은 공개 저장소에 넣지 않습니다.

이관 후 연도별 43 / 26 / 24 / 26건과 총 119건, 상태 및 비고를 대조하고 다른 직원 계정에서 다시 확인합니다. 실제 현장 자료와 관련 없는 기본 예제는 공용 목록에 자동으로 추가하지 않습니다.

## 저장과 충돌

수주 데이터는 서버 인증 후에만 조회·변경됩니다. 세션은 HttpOnly·Secure 쿠키에 저장하고, 직원 허용 목록을 요청마다 확인합니다. 상태 변경·수정·CSV 가져오기·삭제는 DB 저장 성공 후에만 완료됩니다. 서버 장애 시 로컬 저장으로 자동 전환하지 않습니다.

목록 revision을 비교하는 단일 UPDATE로 동시 변경 시 덮어쓰기를 차단합니다. 충돌이 나면 수정 내용을 복사해 두고 수정 창을 닫은 후 다시 열어 최신 자료에 반영합니다. 변경 없는 조회는 포커스 복귀와 10초 간격으로 갱신됩니다.

현재 연결 설정이 없으면 공유 모드는 사용할 수 없습니다. 기존 서비스는 `VITE_SHARED_ORDERS=false`에서 기존 로컬 저장 방식으로 동작합니다. 초기 공유 연결을 완료하기 전에는 기능 플래그를 켜지 않습니다.
